# Report template

Write the report in the user's language. Lead with the verdict. Keep each section short.

```markdown
# Quality audit: <page or template name>

**Verdict:** <Strong | Solid with gaps | At risk | High risk> (<score>/16, <commodity class>)
<One or two sentences on the main reason.>

## Page purpose
<One line.> YMYL: <yes/no and why>.

## Four pillars
| Pillar | Score | Evidence | Fix |
|---|---|---|---|
| Effort | x/4 | <quote or concrete observation> | <specific action> |
| Originality | x/4 | ... | ... |
| Talent or skill | x/4 | ... | ... |
| Accuracy | x/4 | ... | ... |

## Commodity check
- Swap test: <result>
- Top 10 test: <result, "partly checked" if you only saw titles and snippets, or "not checked">
- Only-you assets used: <list or "none">
- Non-commodity angle to produce: <one concrete idea using the user's own assets>

## Red flags
<Only flags supported by evidence, each with the guideline section. "None found" is a valid answer.>

## Template and site view
<Only if context was provided: pages per template, focus fit, recommendation per template: improve / consolidate / move out / remove or noindex.>

## Related Google signals
| Finding | Signal | Evidence |
|---|---|---|
| <finding> | `<attribute>` | Description [Documented]; link to the finding [Inference] |

## Priority actions
1. <Highest-impact action>
2. ...
3. ...

<Only if the site lost traffic in a core update or the user asks about recovery:> Expect changes to show over 3 to 6 months, or at the next core update.
```

For several pages, add a summary table at the top (page, score, commodity class, verdict) and then one short section per page.
